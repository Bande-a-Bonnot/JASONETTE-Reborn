## Diagnosis and contract

The normal Action fixture (`Jasonpedia/action/index.json:235`) has a
`$media.picker` action whose success continuation shares the picked image. It
has no error continuation. `MediaCapturePicker.Coordinator` reports native
Cancel as `ActionError.mediaCaptureCancelled`; sheet dismissal also reports
that outcome. The native continuation is cleared before resumption, preventing
the dismissal callback from completing it again.

`ActionDispatcher.captureMedia` updates local media fields and `$jason` only
after successful capture. It already rethrows cancellation without displaying
its capture-specific alert. `execute` then reaches the generic catch branch
(`ActionDispatcher.swift:334`), which displays `Action failed` when there are
no authored error actions. That is the observed extra dismissal.

Suppressing that alert alone would leave a second defect: private `execute`
catches the cancelled child and returns its incoming payload. An enclosing
success array can then run its later `$util.share` sibling, potentially sharing
previous media. Named `trigger` and `$lambda` wrappers similarly treat the
child's return as successful. Selected utility-picker item actions and timer
action arrays also call the private executor.

Root confirmed the acceptance boundary on 2026-10-02: media cancellation is
terminal for the enclosing success/share flow, including sibling arrays and
named wrappers. Run the cancelled action's authored error continuation once
using its existing incoming-payload contract, then stop the cancelled success
flow. Ordinary non-cancellation failure/recovery behavior stays intact.
Existing error continuations do not receive a newly synthesized error payload;
their execution is the cancellation outcome notification in this contract.
Authored error actions may deliberately update their own state or show an
alert; cancellation itself must not replace selected media or `$jason`.

## Intended implementation

Use the smallest private propagation mechanism within `ActionDispatcher`:

1. Add a private cancellation marker and make the private recursive `execute`
   capable of propagating that marker. The public `execute(_:) async` signature
   remains the action/UI boundary that consumes cancellation quietly.
2. When dispatch throws exactly `ActionError.mediaCaptureCancelled`, execute
   that action's authored error actions in order, with the existing incoming
   payload chaining. After they finish, propagate the private marker.
3. Handle the propagated marker before generic error handling so enclosing
   actions neither show generic feedback nor run a second error continuation.
   The marker unwinds enclosing success arrays before later siblings run.
4. Carry it through named trigger, `$lambda`, and selected utility-picker item
   delegation. At the timer's current tick boundary, stop remaining tick actions
   and preserve existing timer cleanup. Future independent invocations remain
   usable; avoid mutable dispatcher-wide cancellation flags.
5. Keep all non-cancellation dispatch errors on the existing feedback/error
   recovery path. `captureMedia`, native presentation, payload storage, and
   permission checks already expose the required distinction.

Implementation details may be simplified during coding, but the propagation
must stay typed and specific to media cancellation. Do not classify arbitrary
`CancellationError` or unrelated picker/scanner cancellation as this outcome.
