## Diagnosis

The Jasonpedia textfield fixture authors `#f5f5f5` for the body and heading,
and `#ffffff` for its horizontal rows. It omits foreground colors for the
heading and all three fields. The retained dark screenshot shows a white
heading on light gray and dark gray placeholders on black native field
surfaces. The restored-light screenshot confirms that appearance alone
changes these defaults.

`JasonetteView.documentBody` paints the authored body background without
establishing a matching foreground or control appearance. Every component
uses `JasonStyleModifier`, which applies a foreground only when its resolved
style authors `color`. Nested layout children therefore inherit the host's
system appearance even when a parent paints a fixed light surface.

`TextFieldComponent` uses implicit native placeholder styling and
`.roundedBorder` for plain and secure fields. It receives no resolved style.
`TextAreaComponent` receives the resolved style and paints a custom authored
or system fill, but its entered text inherits system foreground and its
placeholder is always `.secondary`. Its authored background is also painted
by the outer style modifier, which would composite translucent input fills
twice. `FooterInputView` is a separate structural renderer using the same
implicit textfield defaults; it should consume the same input policy.

The current tests check CSS parsing, style merging, secure routing, textarea
affordances, and input bindings. They do not cover foreground selection,
placeholder contrast, background inheritance, or appearance propagation.

## Chosen policy

Use the nearest rendered CSS background to select default foregrounds and
local native control appearance. Carry both the effective background and any
inherited authored foreground through a small SwiftUI environment context.

1. Seed the document context from its existing background precedence:
   `body.background` string before `body.style.background`. With no supported
   authored color, use the current system light/dark canvas as the fallback.
   Body `style.color`, when present and parseable, seeds authored foreground.
2. At each component boundary, resolve classes and inline style with the
   existing resolver. Composite a supported background over the inherited
   effective background; preserve inherited context when none is present.
   A fully transparent background does not change the context. Unknown,
   invalid, and image backgrounds do not supply a guessed color.
3. Keep a resolved explicit `color` unchanged. An omitted child `color`
   preserves an authored ancestor foreground. A child explicit color wins.
   Default foreground is computed only when no authored foreground applies.
4. For a known effective surface, choose opaque black or white by the greater
   relative-luminance contrast. Use the same result to select a local light or
   dark control environment. This is a subtree environment value; no global
   preferred appearance or system setting is changed by the renderer.
5. Plain textfields, secure fields, textareas, and footer fields use one input
   appearance resolver. Default input fill is the matching light/dark control
   surface. A field's explicit background is painted exactly as authored and
   exactly once. Default entered text is selected against the actual control
   fill, rather than a different enclosing row surface.
6. Make placeholder color explicit. With an authored foreground, preserve
   that color for the prompt as well as entered text. Otherwise prefer a
   softened version of the computed primary foreground only when its
   composited contrast against the input fill is at least 4.5:1; use the primary
   foreground when softening would fall below that threshold. This target is
   for renderer defaults; authored colors are never rewritten to meet it.
7. Preserve existing names, bindings, initial values, keyboard selection,
   secure masking, Done submission, placeholder text/accessibility, authored
   borders, sizing, and layout behavior. Use conditional modifiers for optional
   authored colors and `strokeBorder` for any default input border.

Extract numeric CSS channels from the existing parser into one shared scalar
representation for luminance and alpha composition. Existing `Color(css:)`,
`Color(hex:)`, and `Color(cssRGB:)` should delegate to that representation and
retain their current supported grammar and rejection behavior. This avoids
two parsers disagreeing about whether a background is actually rendered.
No new `JasonStyle` properties are needed.

## Independent xhigh review repairs

The fresh independent reviewer identified two P2 interactions on 2026-10-02.
The root dispatched these concrete repairs to the same 107 worker:

1. **Persistent tab tint precedence.** The generic component appearance
   modifier installs an inner foreground, overriding the persistent tab
   cell's outer accent/secondary tint. Move the tab's existing tint inside the
   styled content. A small shared tint resolver retains selected accent,
   unselected secondary, authored color, and the existing 0.55 unselected
   dimming. Badges retain their explicit white/red fills, and the selected
   indicator retains its explicit tint fill. New semantic regressions cover
   unstyled/invalid-color fallbacks and authored/class/inline color behavior.
2. **HTML background precedence.** Canonical HTML backgrounds replace the
   CSS fallback in actual body rendering. The appearance resolver previously
   used discarded `body.style.background`, producing an incompatible default.
   Todo 106 provides the shared `JasonBody.htmlBackground` selector. When it
   selects HTML, appearance ignores the discarded CSS background and uses
   the system canvas fallback; arbitrary HTML does not supply a guessed solid
   color. Existing string precedence remains unchanged, and invalid HTML
   objects still fall back to the rendered CSS color. Three regressions cover
   inline/URL HTML in both schemes, invalid objects, and explicit foreground.

The narrow structural caller audit found only the registry, persistent
`FooterTabCell`, and legacy `FooterTabItemView` use the generic modifier.
The legacy renderer has no outer caption/icon tint to be overridden, and its
badge/indicator already apply explicit fills; no additional edit is needed.
