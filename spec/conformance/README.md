# Conformance Test Suite

## Structure

Each test case has its own directory:

```
spec/conformance/
  manifest.yaml        # Test case metadata
  each/input.json      # Input fixture (Jasonpedia source)
  if/input.json
  inline/input.json
  template-index/input.json
  agent/input.json
  invalid/             # Adversarial negative test cases
```

## Manifest Format

Each entry in `manifest.yaml`:

- `id` — Unique test case identifier
- `description` — What the test validates
- `input` — Path to input JSON (relative to this directory)
- `tier` — Action tier (1, 2, or 3)
- `spec_section` — Section of `spec/jason-v2.0.md` being tested
- `tags` — Searchable tags

## Phase 0 Scope

Input fixtures only. Expected output will be generated by the template engine in Milestone 2.

## Invalid Test Cases

The `invalid/` directory contains adversarial inputs that implementations MUST reject:

- `prototype-pollution.json` — `__proto__` in template expression
- `recursive-mixin.json` — Infinite mixin recursion
- `expression-complexity.json` — Excessive expression nesting
- `javascript-url.json` — `javascript:` scheme in href
- `file-url-mixin.json` — `file://` scheme in mixin
- `oversized-document.json` — Exceeds size limit (placeholder)
